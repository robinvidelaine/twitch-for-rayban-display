# Contraintes permanentes

- Web App expérimentale Twitch pour Meta Ray-Ban Display (600×600) et Meta Neural Band. Interface française, flèches et Enter, focus très visible. Garder les tests Chrome PC possibles.
- Architecture 100 % frontend, hébergement statique compatible GitHub Pages. Préférer HTML/CSS/JavaScript natifs et API Web standards ; minimiser les dépendances.
- Aucun backend, serveur applicatif, PHP, Node côté serveur, base de données, proxy vidéo, stockage distant de comptes, analytics ou tracking ajouté. Un outil local servant les fichiers statiques est acceptable pour tester. Demander explicitement avant tout backend.
- Embeds et API Twitch officiels uniquement. Aucun contournement ni récupération directe HLS. Déterminer le parent des embeds depuis le hostname.
- Ne jamais ajouter client_secret, access token, refresh token, mot de passe ou identifiant personnel au dépôt. Les futurs tokens et données privées doivent rester uniquement dans le navigateur/runtime.
- Aucun requestFullscreen : plein viewport en CSS. La bascule du chat doit conserver l’instance et la source vidéo.
- Barre horizontale Chat / Lecture-Pause / Volume / Qualité. Gauche/droite naviguent toujours. Volume : haut/bas ajustent, Entrée mute/unmute avec niveau conservé. Qualité : haut/bas supérieure/inférieure, Entrée Auto uniquement si retourné. Aucun mode édition. Trier les qualités réelles par résolution/fréquence, aucune résolution inventée.
- Bug reproduit sur flux réel : l’ancien panneau recouvrant le lecteur déclenche PAUSE sans appel applicatif. Garder les commandes temporairement SOUS la vidéo, jamais au-dessus de l’iframe ; ne pas forcer une reprise pour contourner Twitch. Aucun hack du DOM/CSS interne, masquage des contrôles natifs ou élément permanent interceptant l’iframe.
- Une seule instance Twitch.Player. Au READY tenter play avec son ; sur PLAYBACK_BLOCKED pendant cette tentative, passer en muet et réessayer une seule fois. Confirmer avec PLAYING ; aucune boucle ou contournement. autoplay:false dans le constructeur évite une tentative concurrente. Une commande utilisateur de lecture annule le fallback en attente. Afficher/masquer l’UI ne commande jamais play/pause. État audio via getMuted/getVolume, jamais une intention locale.
- Consommer keydown/keyup parent, éviter doubles activations et répétition d’Entrée. Diagnostic : clic dans l’iframe capture les flèches ; démarrage par API seul n’a pas reproduit cette perte. En mode Web App, restaurer le focus parent après transfert dans une iframe via événements DOM standards, sans accès interne ou couche bloquante. Mode natif explicite avec bouton de retour hors iframe ; les touches cross-origin n’y sont pas interceptables. Valider cette politique sur Neural Band.
- Chat POC : Twitch Chat Embed officiel restauré, parent réel, modes Masqué/Compact, iframe créée au premier affichage puis conservée. Pas d’OAuth/EventSub pour cette étape. Lecture possible sans login selon disponibilité/restrictions Twitch ; garder l’UI native intacte, aucun scraping ou accès DOM/CSS interne. EventSub reste seulement une option future de rendu personnalisé.
- Chat compact : priorité width:100% et aspect-ratio:16/9. À 600×600 : vidéo 337,5 px stable ; chat 262,5 px barre fermée, 150,5 px avec barre 112 ouverte. Chat flexible, aucun espace mort ni déformation. Ne superposer la barre à aucun embed ; aucune recréation du lecteur.
- Twitch Chat Embed = solution temporaire de POC. Il ne fournit pas le contrôle visuel nécessaire pour le chat final. Cible envisagée : EventSub WebSocket + channel.chat.message ; ne pas implémenter à cette étape.
- La documentation Chat Embed ne propose aucun mode messages seuls/lecture seule ni suppression des éléments natifs. Conserver l’embed pour ce POC ; EventSub avec rendu propre est une option future à décider après essais lunettes, pas à implémenter sans demande.
- OAuth : Client ID public autorisé au dépôt, jamais de secret/token. Vérifier le type de client enregistré : Twitch limite actuellement le type Public au Device Code Grant ; ne pas supposer Public + Implicit. DCF sans secret à étudier pour les lunettes ; Implicit frontend documenté pour une inscription compatible. Expliquer la configuration avant implémentation.
- Avant toute API Meta spécifique, vérifier la documentation officielle actuelle. Privilégier les événements standards. Distinguer vérifications simulées, flux réel et essais sur lunettes.
- Maintenir le README avec lancement, limites et procédure de test. Ne pas choisir de licence sans instruction utilisateur.

- Nouvelle étape autorisée : préparer Connexion Twitch, Suivis, Parcourir, Recherche et chat EventSub lecture seule. Voir ARCHITECTURE.md. Arrêt avant implémentation OAuth tant que la configuration Developer Public et son Client ID ne sont pas fournis. Aucun secret. Cette étape remplace le report du chat personnalisé après les essais lunettes.
- Chat final : EventSub WebSocket + channel.chat.message, rendu local minimal. Chat Embed conservé uniquement pendant la transition. La barre pourra recouvrir notre chat local, jamais le player. Chat ON/OFF ne commande aucune méthode vidéo/audio/qualité.
- Étape UI autorisée avant OAuth : accueil Suivis / Parcourir / Recherche, données locales explicitement fictives, aucune fausse connexion ni API Helix. demo-data.js fournit la source remplaçable ; menu.js porte navigation et restauration du focus/défilement. Aucun clavier virtuel complexe sans vérification Meta.
- Le player est initialisé à la première ouverture depuis le menu, une seule fois. Échap retourne au menu lorsque reçu par le parent ; garder la limite du mode iframe natif. Le retour préserve onglet/carte/scroll et ne commande ni lecture ni audio. Tous les exemples ciblent le CHANNEL de test actuel.

- Correctif Chat/Pause : le redimensionnement réel de l’iframe de 600×600 à 600×337,5 a reproduit PAUSE sans commande applicative. Conserver la géométrie 16:9 stable en haut même Chat OFF (zone inférieure noire). Chat et barre n’altèrent plus le rectangle du player ; aucune reprise forcée. Barre 68 px, aucun panneau status/hint visible.
- UI actuelle : focus bleu clair très visible, cartes horizontales avec vraies miniatures Get Streams (Search Channels retourne une image de profil), titre deux lignes. Aucun faux aperçu ou viewer count. Navigation existante et retour focus/scroll à préserver.
